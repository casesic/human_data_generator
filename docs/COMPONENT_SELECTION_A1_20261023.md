# 四类组件独立选择接入（2026-10-23）

当前唯一场景格式为 `human_scene_v2`。每个 `person_id` 分别保存 `body`、`motion`、`clothing`、`hair`、`motion_start` 和路线；旧 `asset` 字段被严格拒绝。`config/resources.json` 仅定位四份 `config/catalog/*.json`、环境和标定。`python -m human_data_generator.components` 只读展示每类 ID、默认版本、用途、动作有效帧范围、状态、来源说明与限制，不加载模型或构建缓存。添加同格式资源只需更新目录文件，不必编辑 Python 的 ID 列表。

本机目录去重后列出 **19 个身体版本（15 个可用，分属 10 个默认身份版本；4 个早期 10-beta 版本需转换）、12 条动作记录（7 条已转换可用、3 条仅有原始线索、2 条已被当前转换版本取代）、35 件衣物记录（10 件普通可重绑、1 件 M03/KIT11 锁定缓存可用、24 件旧绑定/姿态派生/原始版本暂不可用）、18 个发型版本（10 个可用、8 个早期版本缺当前转移所需 mask 或校正文件）**。扫描到的 93 份历史 `clothing_manifest.json` 中，多数是同一衣型在不同身体/动作帧上的派生拷贝；目录保留不同衣型/材质的代表来源，不把每一帧派生当成一件新衣服。F04 的 v1/v2/v3、F05 的 v1/v2、M02/F02 的 v2/v3 明确作为同一身份家族的版本，不计为新人物来源；默认是 F04_v3、F05_v2、M02_v3、F02_v3。更早的 F01/F02/M01/M02 v1 仅有 10 维 betas，当前 30-beta 构建不直接放行；commuter repair manifest 是已列 v2 的历史修复记录，不另计新人。M02/F02 的可用 groom 默认为 v5，早期 v1–v4 显示缺件原因。7 条可用动作含 5 条骑行、KIT425 与 KIT11 两条走路；p1 两个窗口保留同一来源组。KIT314、SOMA1/2 只有调查到的动作来源索引，缺已转换的 SMPL-X 参数和权威时间表，不能直接选择。资源许可仍由各自目录记录，不因能读文件而改变。

`plan`、目录查询、编辑器 CPU 检查与保存只读。`prepare` 根据选定动作时间窗口按需用**目标**身体的 30 维 betas 和性别加载标准 SMPL-X，把动作姿态移到目标形状；检查手部/表情基、10475 点和面片顺序、整数时间与 root 策略。身体缓存按身体/动作/窗口分离，普通衣物按目标身体逐帧重绑并缓存，静态 groom 通过已有头皮三角绑定转到目标 rest 头部，仅保存一份新静态点集；已有同一 rest 几何则直接引用源 groom。缓存位于生成器 `outputs/cache/components/`，键包括组件版本、窗口、实际输入的路径/大小/修改时间，`complete.json` 最后写入。输入变化使用不同键；已有目录缺文件或完成标记直接拒绝，失败现场不会被当作命中。正常代码不导入旧 DenseKP 运行模块。

M03/KIT11 的 BEDLAM 转移衣物只在原身体、动作、源帧 `[0,120)` 内引用既有仿真结果，按需截取小段衣物缓存，并回核重新计算的目标 body 与历史身体顶点/面片；它**不**允许换身体或动作，发型可以独立换。渲染材质描述引用已有 diffuse/normal 与 UV，CPU 已核对衣面/UV 面片数一致。旧通勤衣物缺当前简单材质/形变合同，未冒充任意可重绑衣物。普通衣物只是固定重心绑定与法线偏移，不是新布料模拟；发型是静态头皮转移，不宣称碰撞或观感已全部验收。

真实短窗口 CPU 验证覆盖：M01/APD 原组合的 body/head 与旧缓存逐值一致；同一 M01 换 `p1_comfortable`，同一场景两个人可共享 APD 动作而使用不同身体；M03/KIT11 行走换 M02 简单衣物及 M01 groom，body 与旧 M03/KIT11 缓存一致、根运动只在动作参数和场景矩阵按既定策略使用；同一 M03/KIT11 改用锁定 BEDLAM 衣物并保留独立 M01 groom。新行走组合完成 2 帧、双 rig 的完整 CPU prepare（8 次相机规划），锁定衣物完成 2 帧单 rig prepare，规则采样的双人交错和 F05/KIT11 跨衣发走路场景各完成 2 帧 prepare。`asset_manifest` 的身体、衣物、发型、时间和材质路径可被当前装配/消费入口直接读取；未启动 Blender 核查材质实显或生成新 RGB。选定帧预览仍只构建所需源动作窗口，旧未选帧在内部时间记录中不具备可消费的本地几何索引。

隔离测试检查目录计数/状态、同 seed 采样、重复组件但不同 `person_id`、未知 ID、旧字段拒绝、锁定衣物错身体/动作拒绝、依赖变更键变化、半成品拒绝、编辑器 `/api/components` 与保存修订，以及当前 consumer/export 原合同。编辑器测试直接调用隔离 Handler，未绑定原服务端口。第一次跨发型 prepare 暴露转移 groom 缺 `groom_manifest.json`；旧试验目录保留，修正后在独立 `prepare_new_combo_v2` 重验通过。检查摘要见 `outputs/acceptance/component_selection_a1_20261023/checks.json`。

导出继续是 `mamma_bundle_v1`，每个人的 RGB/mask、512 点 XY、visibility 和 absent 语义不变；MAMMA reader 无需原组件缓存。未做 Blender、GPU、MAMMA/DenseKP 网络、分割、训练或新 RGB 渲染，不能把 CPU 组合通过称为全部组合的真实画面验收。新编辑器需在用户稍后**另行启动**才会加载四类选择，既有进程本轮未动。
